# Backend tests (`packages/src/backend/tests/`)

Run with `npm test` in `packages`, which runs `node --test --test-concurrency=1 "src/backend/tests/*.test.js"` using the built-in `node:test` runner and `node:assert/strict`. CI runs them too. **Every test uses its own temporary folder** for the database and jobs, and runs the **real `server.js` in a child process with no `.env`**, so the tests never touch `data/app.db`, `jobs/`, or a developer's settings. No test ever trains a model: the COLMAP and Brush paths point at files that do not exist.

## Shared helpers

### `helpers.js`
| Export | Behaviour |
|---|---|
| `BACKEND_DIR`, `REPO_ROOT`, `SAMPLE_PHOTO` | Paths. `SAMPLE_PHOTO` is `Sample Image Set/0001.jpg`. |
| `tempDir(name)` | `mkdtemp` under the system temp folder (`genesis-test-<name>-…`). Every folder is deleted when the test process exits; on Windows, a file still open is left for the system's temp clean-up. |
| `isolatedEnv(dir, extra)` | Copies `process.env` but **removes every backend setting** (`BACKEND_SETTING_RE`: `AUTH_`, `VM_`, `GOOGLE_`, `SMTP_`, `RATE_LIMIT_`, `PORT`, …) a developer's shell might have set. Then sets `ENV_FILE` to a missing file, `AUTH_MODE=local`, `DATA_DIR`/`JOBS_DIR`/`ENGINE_SAMPLES_DIR` inside `dir`, COLMAP and Brush paths that do not exist, fixed flags, and finally `extra`. |
| `freePort()` *(private)* | Listens on port 0 to get a free port from the OS. |
| `startServer(dir, env)` | Spawns `node server.js` on a free port and collects its log. It polls `/api/v1/catalog` every 100 ms (up to 30 s) until the server answers or exits. Returns `{ base, exited, pid, exitCode (getter), log(), stop() }`. |
| `call(base, method, path, { cookie, json, body, headers })` | One `fetch` with `redirect: 'manual'`. The body is parsed as JSON, text or YAML depending on the content type. Returns `{ status, headers, body }`. |
| `sessionCookie(reply)` | `genesis_session=…` from `Set-Cookie`. |
| `signUp(base, { name, email, password })` | `POST /api/v1/auth/signup`, which must answer 201. Returns `{ cookie, user }`. |
| `openDb(dir)` | Opens the test backend's `app.db`, for checks and test-only changes. |
| `addJobFolder(dir, id, fields)` | Creates a job folder as the pipeline leaves it: `status.json` plus one photo. |

### `simulatedUser.js`
Used by `concurrency.test.js`, `load-test.js` and `stress-test.js`.
- **`userIp(index)`**: a distinct private address for user number `index`, sent as `X-Forwarded-For`. The server must run with `TRUST_PROXY=true`, as it does on the VM behind Caddy, so the per-address limits treat each user as a different person.
- **`runUserSession(base, index, onCall)`**: one whole visit. It signs up, reads the account, the catalog and the jobs, creates, lists, edits, reads and deletes a scene, sends feedback and signs out. It checks every reply, including that the scene list holds **only this user's** scene, and reports `onCall(route, ms, status)`. Resolves to `{ ok, errors[] }` and **never throws**.

### `print-routes.js`
Run as a child process by `openapi.test.js`. It loads the real `server.js` **without letting it listen** and prints every registered route as JSON (`["GET /jobs/:id", …]`).

## Test files

| File | What it covers |
|---|---|
| `adapters.test.js` | The VM adapter checks and converts outside data (bad items are dropped, dates become ms, unknown fields go, URLs follow the browser's version, account and feedback are ms in v1 and ISO on legacy). **`JOB_SOURCES`** switches the source and nothing else (`live`, `sample`, `live,sample` newest first; samples can be viewed but not changed). `status.json` versions: v1 loads, a newer record is skipped with one warning, a hand-edited record keeps its good fields, records without a usable version or status are refused, an older record loads once a converter exists. Job lists are checked against the `openapi.yaml` schema. |
| `auth.test.js` | Sign-up sets an **HttpOnly** cookie. A wrong password and an unknown email get the **same 401**. **Every documented protected endpoint (from `openapi.yaml`) answers 401 without a session**, and lets a signed-in user through. A made-up token is refused. Passwords and session tokens are **stored only as hashes**. Only admins read the feedback inbox. Logout ends the session. The VM's machine-to-machine routes need the shared key, and the role comes from the VM's own database. `verify-account`. **10 wrong passwords lock the email, even for the right password (429).** |
| `concurrency.test.js` | **30 users** run a whole visit at the same moment with no errors and no 5xx, each seeing only their own scene, and the database totals add up. **25 simultaneous edits** of one scene all succeed, and reads in between always return a whole scene. **8 uploads plus 4 rejected ones** while 10 users browse: the queue empties and rejected uploads leave nothing. The server still answers quickly afterwards. Every test has a timeout, so a freeze or deadlock fails instead of hanging. |
| `google.test.js` | Runs against a **fake Google** (a small local server standing in for the account chooser and the token endpoint). The full team-machine loop signs the browser in as the VM account, and the role comes from the VM. The one-time code works **once** and **expires**. Redeeming needs the key. The finish link works only in the browser that started the sign-in. A refusal at Google goes back to the team machine. A VM-started sign-in still ends on the VM. **The VM never returns the browser to an address it does not allow.** A machine that cannot redeem codes has no finish step. |
| `migrations.test.js` | A clean database is built from the command line, and a second run does nothing. A database from **before migrations** (text dates) is upgraded and keeps its data. A database newer than the code is refused. A **failing migration rolls back** and leaves the version alone. A gap in the numbering is refused. |
| `openapi.test.js` | **The document:** valid OpenAPI 3.1; documents **exactly the routes the server registers** (through `print-routes.js`); unique `operationId`s, summaries and tags; examples for every request and response; every JSON example matches its schema. **The server answers as documented:** catalog, auth and account, jobs, scenes, performance and feedback replies match the documented status and body shape. |
| `password-reset.test.js` | Emails go to `MAIL_OUTBOX_DIR`, and the tests read the code from there. The full reset (the old password and sessions stop working, a "password changed" email is sent). An unknown email gets the same answer and no email. 5 wrong codes kill the code. Expiry (a TTL of 6 s for the test). One request per minute. The password rule. A bad body. **Codes are stored only as hashes.** A team machine goes through the VM and its sessions end. The VM's limits reach the team machine. "Not set up" answers. 10 requests per IP per hour. |
| `performance.test.js` | Histogram buckets and percentile maths (an even spread over 1–1000 ms; never above the maximum; empty means `null`). API calls counted under their route, the same for `/api/v1` and legacy. A `/library` call is not counted as the plain route. Page-load reports and their per-IP limit. Only admins read the report. The numbers **survive a restart** and old ones are deleted. |
| `queue.test.js` | One build at a time per user while different users run at the same time. A user is not held up by another user's waiting builds. A machine limit of 1 serves first come, first served, and each job is told its place. A machine limit still lets the per-user limit decide who goes next. `maxPerOwner 2`. A cancelled waiting job leaves the queue. A failing build does not stop the queue. **After a restart**, waiting builds resume with their settings, started ones are marked interrupted, and folders without a `status.json` wait. |
| `ratelimit.test.js` | `createLimiter` (blocks until the window ends; `check` does not count; `reset`; `max 0` is off). Wait messages (minutes up to 90, then hours). The general API limit: guests get 429 with `Retry-After`, signed-in users have their own allowance, shared-key calls are not counted, an unknown path is counted once, 0 means off. Build limit: only accepted builds count, and admins are exempt. Download limit: only full downloads count. |
| `scenes.test.js` | A v0 scene is converted and saved as v1. Loading returns exactly what was saved, including after a restart. Saving again keeps `createdAt` and moves `updatedAt`. A browser scene can be saved under its own id. Invalid and newer scenes are refused. Users see only their own scenes. A team machine saves through the VM. **Large scenes**: 500 objects save and load back exactly, the list counts the objects, and a body over 2 MB gets a JSON 413. |
| `secrets.test.js` | **No secrets in the repository**: no tracked file holds a key-shaped value, `.env` files are ignored by git and none is tracked, and the frontend never mentions the server-only secrets. |
| `thumbnails.test.js` | A Node stand-in replaces `make_thumbs.py`, so Pillow is not needed. Cards asking at the same time share one run and get the WebP copy. Later requests are served from disk. Without `size` the original is sent. Other sizes are refused. 401 when not signed in, 404 for someone else's job. The original is sent when no copy can be made. On the VM with `FILE_STORE=db`, copies are made from the database and the temporary folder is removed. The real script is tried if Python has Pillow (otherwise the test is skipped). |
| `versions.test.js` | v1 sends ms and ISO text goes to legacy, for users, account details and feedback. Job URLs follow the version. Legacy replies are marked **deprecated** with the v1 successor. Video upload limit messages are the same on both paths. An unknown version or path is a JSON 404. The catalog is `catalog.json` plus the config limits, and feedback categories come from it. **A broken catalog, or a typo in `JOB_SOURCES`, stops startup.** |
